1. A ideia em uma frase

Treinar = mostrar um exemplo, deixar a IA chutar a resposta, medir o quanto ela errou e ajustar um pouquinho os números dela para errar menos. Depois, repetir isso várias vezes.

É isso. O resto deste PDF mostra onde cada pedaço disso acontece no código, com os números reais.

2. O que é a IA por dentro

A IA é um programa com uma quantidade enorme de números, chamados pesos. O Qwen que usamos tem 494 milhões deles.

Analogia: imagine uma mesa de som com 494 milhões de botões de volume. O texto entra de um lado, passa por todos os botões e sai do outro lado um palpite da próxima palavra. Quem decide se o palpite é bom ou ruim é a posição de cada botão.

A IA escreve uma palavra de cada vez: ela chuta a próxima, junta ao texto, chuta a seguinte, e assim por diante.

O Qwen já veio treinado pela Alibaba com uma montanha de textos. Ele já sabe português e já sabe conversar. Só não conhecia o sistema da nossa biblioteca: por isso errava e até inventava telas, como "Consulta de multas", que não existe.

3. Primeiro: o texto vira números

A IA não lê letras, só números. Então o texto é picado em pedaços, chamados tokens, e cada pedaço tem um número fixo. O Qwen conhece 151.665 pedaços diferentes. Veja a pergunta real do nosso treino:

O46 le512itor1919 trou25410xe8371 o297 livro81423 de409 volta53986.13

E a resposta certa, que a IA precisa aprender a escrever:

Ab5830ra956 a264 tela69766 Dev6040olu43806ção5903 de409 liv15120ros3630.13<fim>151645

O pedaço <fim> é um token especial que significa "terminei de responder". Ele também é ensinado, para a IA aprender a parar depois de indicar a tela.

4. Como fica um exemplo de treino

Cada exemplo é uma conversa completa, com três partes:

ParteConteúdoTokens
Sistema (instruções + lista das 12 telas)"Você é o assistente de um sistema de biblioteca... Telas disponíveis: ..."157
Usuário (a pergunta)"O leitor trouxe o livro de volta."
Assistente (a resposta certa)"Abra a tela Devolução de livros."13

São 170 tokens no total. Mas só os 13 da resposta são corrigidos. Os 157 primeiros são marcados com o número especial -100, que quer dizer: "não corrija esta parte".

Por quê? Numa prova, o professor corrige a resposta do aluno, não o enunciado. Se corrigíssemos tudo, a IA gastaria esforço aprendendo a repetir a pergunta, o que não serve para nada.

No código, é esta função do arquivo scripts/treinar.py:

def montar_exemplo(tokenizer, item):
    # a conversa SEM a resposta (sistema + pergunta) -> 157 tokens
    prompt = tokenizer.apply_chat_template(mensagens(item["pergunta"]), tokenize=False,
                                           add_generation_prompt=True)
    # a conversa COMPLETA (sistema + pergunta + resposta certa) -> 170 tokens
    completo = tokenizer.apply_chat_template(mensagens(item["pergunta"], item["tela"]),
                                             tokenize=False)
    ids_prompt = tokenizer(prompt)["input_ids"]      # texto -> números
    ids = tokenizer(completo)["input_ids"]
    # gabarito: -100 ("não corrija") na pergunta, e os números certos na resposta
    rotulos = [-100] * len(ids_prompt) + ids[len(ids_prompt):]
    return {"input_ids": ids, "labels": rotulos}

input_ids é o que a IA lê. labels é o gabarito, a lista com as respostas certas.

5. O LoRA: congelar o original e colar "post-its"

Ajustar os 494 milhões de números seria pesado demais para o processador. Por isso usamos o LoRA:

  • os 494 milhões de números originais são congelados e não mudam;
  • são criados 8,8 milhões de números novos (1,75% do total), colados "do lado" de partes do modelo;
  • só esses números novos são treinados.
Analogia: em vez de reescrever um livro de 494 milhões de páginas, você cola post-its nas páginas importantes. O livro continua igual; os post-its mudam o jeito como ele é lido. No fim, você só guarda os post-its: o arquivo de 34 MB, em vez do modelo inteiro de 1 GB. 
config = LoraConfig(
    r=16,                # "tamanho" de cada post-it (quanto maior, mais ele consegue aprender)
    lora_alpha=32,       # o quanto o post-it "pesa" em relação ao original
    lora_dropout=0.05,   # desliga 5% ao acaso em cada passo, para não decorar
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",   # onde colar os post-its:
                    "gate_proj", "up_proj", "down_proj"],     # nas 7 partes de cada camada
)
modelo = get_peft_model(modelo, config)   # congela o original e cola os post-its
# saída real: trainable params: 8,798,208 || all params: 502,830,976 || trainable%: 1.7497

6. O coração: SIM, o treino é um loop

O treino inteiro é um laço (loop) que repete o mesmo ciclo de 5 passos. Este é o desenho do que acontece em cada volta:

E este é o loop de verdade, copiado do scripts/treinar.py, com os 5 passos marcados:

for epoca in range(1, EPOCAS + 1):               # 3 voltas pela lista inteira
    random.shuffle(treino)                          # embaralha os 74 exemplos
    for i in range(0, len(treino), LOTE):           # pega de 8 em 8
        lote = juntar_lote(treino[i : i + LOTE], ...)

        perda = modelo(**lote).loss      # 1. CHUTE  + 2. NOTA  (a IA chuta e já recebe a nota)
        perda.backward()                 # 3. CULPA  (descobre para que lado girar cada número)
        otimizador.step()                # 4. AJUSTE (gira os 8,8 milhões de números)
        agendador.step()                 #    (deixa o próximo giro um pouco menor)
        otimizador.zero_grad()           # 5. LIMPA  (apaga as anotações para o próximo lote)
É só isso. Todo o "aprendizado" está nessas 4 linhas dentro do loop. Na prática, as bibliotecas prontas (Trainer, SFTTrainer, Unsloth) fazem exatamente esse mesmo loop, só que escondido. Neste projeto o loop foi escrito à mão de propósito, para dar para ver.

7. Cada passo do loop, explicado

Passos 1 e 2 — CHUTE e NOTA: perda = modelo(**lote).loss

Os 8 exemplos do lote passam pela IA. Para cada token da resposta, ela dá uma probabilidade para cada um dos 151.665 pedaços possíveis. Por exemplo: "depois de Abra a tela, acho que vem Dev com 40% de chance, Cons com 30%...".

A loss (perda) é a nota de erro: quanto menos chance a IA deu para o token certo, maior a loss. Uma regra prática:

LossChance média que a IA dá para o pedaço certoNo nosso treino
0,40cerca de 67%passo 1 (ainda inseguro)
0,10cerca de 90%meio da 1ª época
0,04cerca de 96%fim do treino (confiante)

Conta: chance ≈ e−loss. Por exemplo, e−0,40 ≈ 0,67.

Passo 3 — CULPA: perda.backward()

Essa linha percorre a IA de trás para frente e calcula, para cada um dos 8,8 milhões de números treináveis, duas coisas:

  • para que lado girar o número (aumentar ou diminuir) para o erro cair;
  • quanto ele contribuiu para o erro.

Esse cálculo se chama gradiente. Nada muda ainda: é só uma anotação ao lado de cada número.

Analogia: você está numa montanha com neblina e quer descer. Não enxerga o vale, mas sente com o pé para que lado o chão desce. O gradiente é essa "inclinação do chão" para cada número.

Passo 4 — AJUSTE: otimizador.step()

Agora sim, cada número é girado um pouquinho na direção indicada. O tamanho do giro é a taxa de aprendizado: 0,0002. É pequena de propósito: com giros grandes, a IA "esquece" o que já sabia e fica instável.

O agendador faz o giro diminuir aos poucos, de 0,0002 no começo até 0 no último passo. É como estacionar um carro: rápido no começo e devagar no final.

O otimizador usado é o AdamW. Ele lembra a direção dos passos anteriores e dá giros mais estáveis, como uma bola que ganha embalo descendo a montanha.

Passo 5 — LIMPA: otimizador.zero_grad()

Apaga as anotações de culpa. Sem isso, a culpa do lote anterior se somaria à do próximo e os giros ficariam errados.

E a linha clip_grad_norm_(..., 1.0)?

É um cinto de segurança: se algum lote der uma culpa absurdamente grande, ela é limitada, para um exemplo estranho não estragar o treino de uma vez.

8. Quantas voltas, e quanto tempo cada uma levou

TermoO que éNo projeto
Lote (batch)quantos exemplos entram juntos em cada volta8
Passo (step)uma volta completa do loop (os 5 passos)30 no total
Época (epoch)passar a lista inteira de exemplos uma vez3 épocas

A conta: 74 exemplos ÷ 8 por lote = 9 lotes cheios + 1 lote com só 2 exemplos = 10 passos por época. Com 3 épocas, são 30 passos.

Tempos reais (tirados de resultados/treino_log.json)

ÉpocaPassosLoss no início → no fimLoss médiaTerminou em
1ª1 a 100,40 → 0,0050,210183 s (3 min)
2ª11 a 200,044 → 0,0740,067363 s (6 min)
3ª21 a 300,027 → 0,0440,040544 s (9 min)
  • Cada passo com 8 exemplos levou cerca de 20 segundos no processador.
  • Os passos 10, 20 e 30 levaram só cerca de 3 segundos, porque eram os lotes com apenas 2 exemplos.
  • A loss "pula" um pouco entre passos (sobe e desce) porque cada lote tem exemplos diferentes, uns mais fáceis e outros mais difíceis. O que importa é a tendência: a média caiu de 0,210 para 0,040.
Por que tão lento? Cada passo com 8 exemplos faz alguns trilhões de contas. Uma placa de vídeo (GPU) faz milhares dessas contas ao mesmo tempo e seria muitas vezes mais rápida. No processador, 9 minutos ainda é bem aceitável para um projeto deste tamanho.

9. Como sabemos que funcionou

Antes do treino, separamos 24 perguntas que a IA nunca viu, como uma prova surpresa. Ela fez a prova duas vezes, com o mesmo enunciado (a mesma lista de telas):

Pergunta (exemplo)Antes do treinoDepois do treino
"Acabaram de chegar livros novos que a escola comprou."❌ Consulta de leitores✅ Cadastro de livros
"Tem algum livro de receitas aqui?"❌ Cadastro de livros✅ Catálogo do acervo
"Quanto custa a multa desse aluno?"❌ Consulta de multas (inventou)✅ Cobrança de multas
"O leitor veio quitar o que deve."❌ Consulta de empréstimos❌ Devolução de livros
Total4 de 24 (16,7%)18 de 24 (75%)

Como essas perguntas não estavam no treino, a IA não decorou as respostas: ela aprendeu o padrão. Os 6 erros que sobraram são de telas parecidas entre si (Multas × Devolução, Reserva × Consulta de empréstimos). A solução seria dar mais exemplos dessas telas.

10. Linha do tempo completa do projeto

  1. Preparar o ambiente: o uv instalou o Python 3.12 e as bibliotecas PyTorch (para CPU), Transformers e PEFT.
  2. Escrever os dados: 12 telas, 74 exemplos de treino e 24 de teste, nos arquivos dados/*.jsonl.
  3. Prova antes (avaliar.py): baixou o modelo (cerca de 1 GB) e mediu 16,7% de acerto.
  4. Treino (treinar.py): 30 voltas do loop em 544 segundos; o arquivo de 34 MB foi salvo em saida/adaptador-lora/.
  5. Prova depois (avaliar.py --lora): carregou o modelo original + os post-its e mediu 75%.
  6. Comparação e gráfico (avaliar.py --comparar e grafico.py).
  7. Publicação no GitHub, com o arquivo treinado na aba Releases.

11. Na hora de usar: como a IA treinada responde

Depois do treino, não tem mais loop de aprendizado. A IA só chuta, sem nota e sem ajuste. Isso se chama inferência:

tokenizer, modelo = carregar(PASTA_ADAPTADOR)   # modelo original + os post-its de 34 MB
gerado = modelo.generate(**entrada,
                         max_new_tokens=32,     # escreve no máximo 32 pedaços
                         do_sample=False)       # sempre escolhe o pedaço mais provável (sem sorteio)

Ela escreve um token por vez, sempre escolhendo o mais provável, até chegar no token <fim> que aprendeu no treino.

12. Resumão

  1. A IA é um monte de números; o texto vira números (tokens).
  2. Congelamos os 494 milhões originais e colamos 8,8 milhões novos (LoRA).
  3. Loop: a IA chuta → recebe a nota (loss) → calcula a culpa de cada número (backward) → gira os números um pouquinho (step) → limpa (zero_grad).
  4. Repetimos isso 30 vezes (3 épocas de 10 passos) em 9 minutos, só no processador.
  5. A loss média caiu de 0,210 para 0,040, e o acerto em perguntas novas subiu de 16,7% para 75%.
